Install

Let an agent do it — paste this into Claude Code, Codex or pi:

Install dokdok: read https://raw.githubusercontent.com/isaaclins/dokdok/main/install.md and follow it.

By hand:

# the CLI (or: pipx install git+…)
uv tool install git+https://github.com/isaaclins/dokdok
# required
brew install pandoc
# for PDF — open it once on macOS after installing
brew install --cask libreoffice
dokdok doctor

Commands

dokdok new <name> --type <doctype>create a project from a doctype (--title, --author)
dokdok check [--final]lint the project against its doctype; --final also rejects placeholders and leftover hints
dokdok render [target] [--pdf]render into out/; docx by default, PDF via LibreOffice
dokdok entry <section> [--date D] [--title T]add an entry to a repeat section, e.g. a journal day
dokdok log --tool T "purpose" [--outcome O]append to the AI usage log
dokdok add <folder-or-git-url>install a doctype into ~/.dokdok/doctypes/
dokdok types listdoctypes available
dokdok types lint [folder]validate a doctype
dokdok types from-docx file.docxmake a doctype from a Word file you like
dokdok doctorcheck pandoc / LibreOffice / Word

Project layout

thesis/
├─ dokdok.yaml      doctype, title, author, optional targets
├─ doc/
│  ├─ 01-introduction.md
│  ├─ 02-main-part.md
│  └─ …             one file per section, in doctype order
├─ sources.yaml     citations (CSL YAML), used as [@id]
├─ ai-log.yaml      written by `dokdok log`
├─ AGENTS.md        the document's rules — generated, read by every agent
└─ out/             rendered files; never edit these

Writing

A section file is plain markdown with one line of front matter:

---
section: introduction
---

<!-- dokdok:hint
Guidance from the doctype. Delete once the section is written.
-->

## Topic and personal motivation

Text with a citation [@survey2025] and a figure:

![Winter cluster (source: own drawing)](img/cluster.svg)
  • The section title (#) comes from the doctype; start your headings at ##.
  • Citations: [@id]. Every id must exist in sources.yaml under references: (CSL YAML — id, type, title, author, issued, URL…).
  • Figures need a caption. Tables: pipe tables followed by Table: caption.
  • Things only the human can supply: leave a visible [placeholder]. check --final finds them.

Doctypes

A doctype is a folder. Only doctype.yaml is required.

my-type/
├─ doctype.yaml     structure, rules, checks, targets
├─ reference.docx   styles, header/footer, logo, margins — edit in Word
├─ AGENTS.md        writing rules, copied into every project
├─ sections/id.md   starting content for a section (optional)
├─ filters/*.lua    pandoc filters (optional)
└─ skills/          agent skills shipped with the type (optional)
name: school-thesis
title: School thesis
lang: en                        # picks the TOC title; override with toc_title
number_sections: true           # false if reference.docx heading styles number themselves
spelling: { no_eszett: true }   # German: error on ß

sections:
  - id: introduction
    title: Introduction
    required: true
    subsections: [Topic and personal motivation, Aim and research questions]
    words: { min: 300, max: 450 }
    hint: Finish this last.
  - id: journal
    title: Work journal
    repeat: daily               # doc/journal/YYYY-MM-DD.md, one ## per file
    entry_title: "{title} – {date}"
  - id: references
    title: References
    generated: sources          # from sources.yaml
  - id: glossary
    title: Glossary
    generated: glossary         # from glossary.yaml (term, definition)
  - id: figures
    title: List of figures
    generated: figures          # numbered captions; also: tables
  - id: ai-log
    title: AI usage log
    generated: ai-log           # from ai-log.yaml
  - id: remediation
    title: Remediation plan
    only_for: [blue-team]       # only in targets with that audience

checks: [every_citation_resolves, every_source_cited, every_figure_has_caption, no_placeholders_in_final]

targets:
  default:   { format: docx }
  blue-team: { format: docx, audience: blue-team }
  web:       { format: html }

From a Word file you like

dokdok types from-docx template.docx --name my-school

Keeps styles, numbering, header/footer and logo (the body is emptied into reference.docx), turns the heading outline into sections and grey or bracketed placeholder text into hints, and tells you what it couldn't carry over (body tables, images, text boxes). Then edit doctype.yaml, run dokdok types lint, and render a skeleton to compare with the original.

Fonts, heading styles, colours, numbering, header/footer, margins and page numbers round-trip. Free-form layouts (text boxes, magazine-style covers) don't — keep those as a static cover.docx.

Targets and audiences

One project, several outputs. A target sets the format and optionally an audience; sections with only_for and blocks like the one below are dropped for other audiences.

::: {.only-for="blue-team"}
**Remediation.** Add `Secure` in `config/session.php`, line 14.
:::
dokdok render exec        # out/<name>-exec.docx
dokdok render blue-team   # out/<name>-blue-team.docx

How agents know about dokdok

Two layers. A global skill (skills/dokdok/SKILL.md in the repo) tells the agent when to reach for dokdok — the repo is a Claude Code plugin and a pi package, Codex users copy the folder. Inside a project, the generated AGENTS.md carries the doctype's rules, so any agent works there without the skill.

Agents are asked to run dokdok check before claiming they're done and to record their sessions with dokdok log.

PDF

The docx contains a live table of contents. Word asks “update the fields in this document?” when you open it — click Yes and the entries and page numbers appear.

dokdok render --pdf converts the docx with LibreOffice, updating the table of contents and page numbers first. On macOS, open LibreOffice once after installing so Gatekeeper stops blocking headless runs. Without LibreOffice, Word is used on macOS if it's installed and the screen is unlocked.
